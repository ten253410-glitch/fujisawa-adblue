# 未請求の後続月請求・統合請求（ローカル版）

操作手順は [請求画面の使い方](BILLING_UI_GUIDE.md) を参照してください。

## ①と②の役割

①は選択した請求月の請求書を作る画面です。その月の未請求通常実績と、②でその月へ追加済みの実績を候補にします。通常請求が発行済みの元月へ、残った請求漏れを混在させません。

②は未請求実績を次に請求する月へ送る画面です。複数選択→請求する月→任意の一括理由→「選択した○件を○月請求へ追加」で処理します。ここでは請求書を作成・確定しません。未記録の発見日は処理日（日本時間）を記録します。

本来の対象月は変更せず、追加先の請求月を別項目として保存します。翌月だけでなく、任意の後続月へ追加可能です。追加済み明細は①で元月未請求分と表示し、通常実績と合算できます。

## Schatzと原本

EG八王子740L×65円＝48,100円、デイライン西東京営業所200L×65円＝13,000円は、本来2026年8月の未請求2実績です。実給液日は8月4日、合計940L／61,100円です。

8月の①の通常候補には表示しません。②から9月・10月等へ送った後、①の追加先月に表示します。追加時点で他の月への二重追加を防ぎ、請求書確定時に請求書IDを記録します。

8月原本のSchatz9,630L／570,290円、全体40,500L／税抜2,823,058円／消費税282,305円／税込3,105,363円は不変です。61,100円を固定調整額にせず、実績2明細の固定売上から計算します。

## 取消・統合・互換性

追加取消は②で理由を付けて行います。下書き使用中は先に①で下書きを取り消す必要があります。確定後の解除は④の管理画面に分離し、原本は解除しません。旧請求書・追加取消履歴を保持します。

③の統合設定で複数給液先を1請求先へ紐付けます。翌月以降の設定と未請求実績だけを変更し、過去の請求済み実績・原本・ID・単価履歴を保持します。①は統合または給液先別で作成できます。

localStorageとJSONバックアップ形式（バージョン5、旧2〜4も読込可）を維持します。元対象月・追加先月・追加者・日時・取消履歴は追加項目として保存し、旧バックアップの単なる「請求予定月」を勝手に追加済み扱いへ変換しません。旧下書き・原本・画像・将来AIコードを保持します。課金・外部接続・本番公開は行いません。
