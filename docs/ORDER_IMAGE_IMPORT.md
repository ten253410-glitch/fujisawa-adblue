# 受注画像取込

## 処理方法

トップの「受注画像取込」から、FAX、紙の受注書、LINE画像を撮影／選択します。JPEG/PNG/WebP、1枚10MB以内。PDF/HEICは画像に変換してください。複数案件を1枚で一括登録する処理はありません。

1. 原画像を選択しプレビュー。
2. AI読み取りは、OpenAIへの画像送信と課金に同意してボタンを押した場合のみ実行。顧客マスターは送信しません。送信用に長辺2400px以内のJPEG（品質0.9）へ変換し、約2.8MB以内に制限します。細かい文字が潰れる場合は近づいて再撮影してください。
3. 顧客名、現場名、住所、依頼数量L、希望給液日、受注日、連絡先、備考と注意点を確認画面に表示。年のない日付・相対日付、本数からLへの換算などは推測しないよう指示し、形式不正の値は破棄します。AIによる誤認識は起こり得るので必ず原画像を確認してください。
4. 顧客マスターとの候補を名前・電話・登録場所から提示。候補は自動選択しません。全顧客からの選択も可能です。主な給液場所／住所は既存の `customers.address` を照合欄に表示します（現行Phase 1の兼用欄）。現場ごとの複数住所マスターはまだありません。
5. 未登録顧客は「新規顧客として追加」で内容を確認。顧客と受注を同時登録します。単価は自動登録しません。
6. 希望給液日とは別に、調整済みの給液予定日を任意入力。希望日の入力だけでは案件は日程未定のままです。単価は対象日の参考値のみで、給液日の実績単価の固定ルールは変更しません。
7. 最後に原画像・顧客・数量・日付の確認チェックを入れ、「確認した内容で受注登録」。フィールドを修正するとチェックは外れ、再確認が必要です。

確認画面の段階では受注や顧客マスターを作成・更新しません。外部AIへ送った画像はOpenAI側のサービス処理対象になります。Responses APIは `store:false` で呼びますが、それだけでサービス全体の保持ゼロを保証するものではありません。実データ送信前に契約・データ取扱条件を確認してください。

## Supabaseの更新

既存DBには `supabase/002_order_images.sql` を一度実行します。**001を再実行しないでください。** 新規DBなら001 → 002の順。既存受注とPhase 1の機能は残します。

追加するもの：

- ordersの住所・連絡先・希望給液日、FAX/紙/画像の受注経路
- privateなorder-imagesバケット
- order_source_images（原画像参照・読み取り候補・修正後・確認者・確認日時）
- register_image_order RPC（確認を必須とし、新規顧客があれば顧客＋受注＋確認記録を同一トランザクションで作成）
- DBの管理者別OCR利用制限（1分5回）

画像の保存は確認登録時だけです。本番では選択した原ファイルをそのままStorageに保存します。読取APIへの入力画像は軽量化版です。メタデータ登録失敗時は孤立画像の削除を試みます。通信障害で登録結果が不明な場合、再登録前に最新データを確認してください。登録済み画像と確認記録はアプリから削除・上書きできません。署名URLは閲覧時に60秒だけ有効。受注の後日の変更は既存監査履歴に残り、初回確認記録も保持します。

migration未適用時も既存Phase 1の一覧読込は継続できますが、画像受注登録はSQL設定エラーになります。OCRの利用回数テーブルは運用に合わせた定期削除が必要です。

## 外部APIの設定

必要なのはOpenAI APIの利用可能なキーと、画像入力＋Responses APIのstrict JSON schemaに対応したモデルです。モデルは明示設定し、未設定時にはAPIを呼びません。利用料金は選んだモデル・画像・トークンによります。この実装はモデル価格を仮定しません。

サーバーの環境変数：

```text
ADBLUE_OPENAI_API_KEY=ここにAPIキーを安全に設定
OPENAI_OCR_MODEL=利用するモデルID
```

APIキーに `NEXT_PUBLIC_` を付けないでください。チャットやGitHubへキーを貼らないでください。コードはOpenAI公式SDKで `https://api.openai.com/v1/responses` を呼びます。ネットワーク制限があれば `api.openai.com` のHTTPSアクセスが必要です。SDKは自動リトライなし、45秒タイムアウト、出力上限2000トークンです。

本番VercelではSupabase管理者ログインを必須とし、Bearer tokenをサーバーで検証します。公開デモのログインだけでは有料APIを使えません。Vercelの環境変数を設定して再デプロイし、Supabaseの002移行も適用してください。Origin照合・入力サイズ制限・管理者別利用制限を設けていますが、運用時はOpenAI側の予算／利用枠も設定してください。

## Windowsのローカルデモで本物の画像を読み取る場合

PCにだけ置く `.env.local` に上記2項目と、次の明示許可を設定します。

```text
ADBLUE_ALLOW_LOCAL_OCR=true
```

`npm run dev` を再起動し、手元PCのlocalhostまたは127.0.0.1で操作します。この許可はNODE_ENV=developmentかつローカルホストのみで働き、本番では無効です。ローカルのAI利用制限はプロセス内で1分3回（サーバー再起動でリセット）。APIキーを設定すると、デモでも画像送信で課金されます。

API未設定でも「手入力で確認へ」が使えます。デモだけにある「サンプル候補で確認画面を試す」は架空の値で、選択画像を解析した結果ではありません。デモで保存する画像は軽量化JPEGであり、保存先はそのブラウザだけです。今回も既存デモデータを削除しません。localStorageの容量を超えると登録エラーになるので、本番データの保存にはSupabaseを使ってください。

## 未実施

実APIの読取精度検証、実FAX画像・手書き・傾いた写真での評価、本番Supabase Auth/Storageとの接続検証、実スマートフォンカメラ。キーとモデルが設定された後、匿名化した代表的な画像で読み取り→修正→登録を確認してください。納品書のOCRは今回の対象外です。

## ローカル運用への変更

現在は有料AIを初期停止しています。APIキーだけでは有効になりません。
ADBLUE_ENABLE_PAID_OCR=true の明示設定と既存のキー・モデル・認証条件が必要です。今回は設定不要です。
画像取込・手入力・候補顧客の選択・原画像確認・確認後登録は無料で使えます。
